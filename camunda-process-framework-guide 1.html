Camunda Process Framework 0.1.1

Multi-module Spring Boot 4 / Java 21 base framework for Camunda 8.9 SaaS — complete architecture, patterns, and developer walkthrough.

Camunda 8.9 SaaS Spring Boot 4.0.5 Java 21 8 Modules · 183 Tests

This framework is a production-grade, opinionated scaffold built by Aaseya for every team building process-orchestrated microservices on Camunda 8.9. It ships pre-wired patterns for job workers, saga orchestration, idempotency, outbox messaging, JWT security, observability, and more — so teams write business code, not infrastructure plumbing.

Design Philosophy — 5 Cardinal Invariants

① BPMN is the source of truth

Every lifecycle lives in a BPMN diagram. Each automated step maps 1:1 to a @JobWorker. Each human step is a Camunda User Task assigned to a Keycloak group.

Camunda

② Workers & Controllers = Adapters only

No business rules in workers or controllers. Business logic lives exclusively in the domain/ layer.

Architecture

③ Orchestration-based Saga

Services never call each other directly for saga steps. Camunda mediates every hop. Rollback = BPMN compensation boundary events.

Saga

④ Domain never imports Camunda

All engine access goes through ProcessService facade. Enforced by ArchUnit at build time. Domain stays pure Java.

Port & Adapter

⑤ Business failure ≠ Technical failure

Business failures throw newThrowErrorCommand → BPMN boundary event. Technical failures rethrow → Camunda decrements retries → incident.

Complete Request & Job Execution Flow

Flow A — Starting a Process via REST

1

HTTP Request arrives

MdcCorrelationFilter reads X-Correlation-Id header (or generates UUID). Puts it in SLF4J MDC. Echoes it back in response header. X-Tenant-Id also pushed to MDC.

2

JWT Authentication

Spring Security validates Bearer token. JwtRealmRolesAuthenticationConverter extracts realm_access.roles from JWT and maps to ROLE_* Spring authorities.

3

Controller receives request

Returns DTO only — never entity. Returns Response.ok(dto) which auto-captures correlationId from MDC + timestamp into the Meta envelope.

4

Domain Service or OutboxRelay

Either calls processService.start(StartProcessCommand) directly, or writes to process_outbox table within the same DB transaction as the domain change (transactional outbox pattern).

5

Camunda cluster starts instance

CamundaProcessService.start() calls camundaClient.newCreateInstanceCommand(). Returns the processInstanceKey. Multi-tenant mode conditionally forwards tenantId.

6

BPMN executes — workers are activated

Camunda activates jobs for service task nodes. The appropriate @JobWorker bean picks up the job.

Flow B — Job Worker Execution (inside BaseWorker.execute())

1

Deserialize variables

Primary: job.getVariablesAsType(V.class). Fallback: VariableMapper.map(job.getVariables(), V.class). On failure → runtime exception (Camunda decrements retries).

2

MDC push

Pushes processInstanceKey, elementId, jobType, jobKey, workerName, tenantId, businessKey into SLF4J MDC for structured log correlation.

3

Idempotency check

IdempotencyGuard.check(businessKey, elementId) queries worker_execution(business_key, element_id) composite PK. If already recorded → complete silently + increment framework_job_replayed_total counter. Return early.

4

validate() hook

Subclass overrides validate(V vars). Throws BusinessException if validation fails → framework converts to BPMN error event. Default is no-op.

5

doWork(vars, job)

Your business logic runs. Returns a WorkResult: Completed, BusinessError, or Compensated.

6

mapResponse() + dispatch to Camunda

Completed → newCompleteCommand().variables(outVars). BusinessError → newThrowErrorCommand(code, msg). Compensated → newCompleteCommand() no vars. Idempotency recorded on success.

7

Exception routing

BusinessException → throwError. RetryableException → rethrow (Camunda decrements retries). NonRetryableException → throwError(TECHNICAL_FAILURE). Unhandled RuntimeException → handleException() hook or rethrow.

8

MDC cleanup (finally block)

All 7 MDC keys pushed in step 2 are removed in reverse order in the finally block — guaranteed even on exception. Prevents MDC leaking across thread-pool reuse.

Flow C — Transactional Outbox (Reliable Process Start)

// In a @Transactional service method:
// 1. Domain change and outbox write in SAME transaction
myEntityRepo.save(entity);
outboxRelay.publishStart(
  StartProcessCommand.withVariables("MyProcess", entity.getId(), vars)
);
// TX commits — both rows in one atomic write

// 2. JdbcOutboxRelay.poll() fires every 2s (scheduled)
//    SELECT ... FROM process_outbox WHERE dispatched_at IS NULL
//    FOR UPDATE SKIP LOCKED  ← safe for parallel pods
//    → processService.start(cmd)
//    → UPDATE process_outbox SET dispatched_at = now() WHERE id = ?

Layer Rules (ArchUnit)

Six ArchRule constants in ArchitectureRules are enforced at build time via JUnit 5 + ArchUnit in any consuming service that adds framework-test.

ONLY_INFRASTRUCTURE_CAMUNDA_MAY_IMPORT_CAMUNDA_CLIENTOnly infrastructure.camunda.. (+ framework itself) may import io.camunda.client.*Prevents accidental engine coupling in domain or workers; enables protocol swap (REST↔gRPC) transparently.

BaseWorker<V> — Deep Dive

BaseWorker<V> is the template-method base class. Every job worker extends it and implements exactly two abstract methods. The framework owns the full execution skeleton via execute() which is declared final.

Methods to Implement

MethodRequired?Purpose
varsType()✅ AbstractReturns Class<V> token. The framework uses it to deserialize the job's JSON variables into your typed record.
doWork(V vars, ActivatedJob job)✅ AbstractYour business logic. Return a WorkResult. Throw only for transient technical failures.
validate(V vars)Override optionalValidate input variables before doWork. Throw BusinessException to route to BPMN error boundary.
mapResponse(WorkResult.Completed)Override optionalTransform output vars before they are sent to Camunda. Filter secrets, add computed fields.
handleException(Exception, ActivatedJob)Override optionalIntercept unhandled RuntimeExceptions. Return a WorkResult to replace the throw, or return null to rethrow.
workerType(ActivatedJob)Override optionalLabel used on metrics. Default returns job.getType().

framework_job_business_error_totaltype=<jobType>, code=<errorCode>BusinessError or BusinessException thrown
framework_job_failed_totaltype=<jobType>RetryableException or unhandled RuntimeException
framework_job_replayed_totaltype=<jobType>Idempotency guard detected already-processed job

Example Worker

@Component
public class ValidateApplicationWorker extends BaseWorker<ValidateApplicationVars> {

    private final ApplicationDomainService domainService;

    public ValidateApplicationWorker(ApplicationDomainService domainService,
                                         VariableMapper mapper,
                                         IdempotencyGuard guard,
                                         MeterRegistry registry) {
        super(mapper, guard, registry);
        this.domainService = domainService;
    }

    @Override
    protected Class<ValidateApplicationVars> varsType() {
        return ValidateApplicationVars.class;
    }

    @Override
    protected WorkResult doWork(ValidateApplicationVars vars, ActivatedJob job) {
        ValidationResult result = domainService.validate(vars.applicationId());
        if (!result.isValid()) {
            return WorkResult.businessError("VALIDATION_FAILED", result.message());
        }
        return WorkResult.completed(Map.of("validationStatus", "PASSED"));
    }

    @JobWorker(type = "validate-application", autoComplete = false)
    public void handle(JobClient client, ActivatedJob job) {
        execute(client, job); // delegate to framework skeleton
    }
}

// Typed variable record (Java 21 record)
public record ValidateApplicationVars(
    String applicationId,   // required — VariableMapper throws if null
    String businessKey,     // required — used for idempotency
    @Nullable String notes  // optional field
) {}

ProcessService — API Reference

ProcessService is the port (outbound interface) that all application-layer code uses to talk to Camunda. CamundaProcessService is the adapter implementation. Domain code never imports io.camunda.client.*.

MethodCommand RecordWhat it does
start(StartProcessCommand)bpmnProcessId, businessKey, variables, tenantIdCreates a new process instance. Returns processInstanceKey. Forwards tenantId only if multi-tenant=true.
correlate(CorrelateMessageCommand)messageName, correlationKey, variables, tenantIdCorrelates a message to a waiting process instance. Fails if no instance is waiting.
publish(PublishMessageCommand)messageName, correlationKey, variables, timeToLive, messageIdPublishes a message to the broker (fire-and-forget). Works for message-start events too. messageId enables deduplication.
completeActiveUserTask(processInstanceKey, vars)—Finds active CREATED user task for the instance (exponential retry, 5 attempts, 200ms base) and completes it with vars.
findActiveUserTaskKey(processInstanceKey)—Returns Optional<Long> — the user task key. Retries 5× because the Camunda search index is eventually consistent.
cancel(processInstanceKey, reason)—Cancels a running process instance. Reason shows in Operate audit trail.

StartProcessCommand — Factory Methods

// Minimal — no variables, no tenant
StartProcessCommand.of("Process_Booking", "BOOKING-2025-001");

// With variables
StartProcessCommand.withVariables(
    "Process_Booking",
    "BOOKING-2025-001",
    Map.of("applicantId", 123, "amount", 5000.0)
);

// Multi-tenant (full constructor)
new StartProcessCommand("Process_Booking", vars, "BK-001", "tenant-a");

WorkResult — Sealed Interface

A WorkResult is the only return type from doWork(). It's a sealed interface with three permits — the framework pattern-matches on them to dispatch the correct Camunda command.

VariantCamunda CommandUse when
WorkResult.Completed(Map variables)newCompleteCommand().variables(outVars)Job succeeded. Output variables are written to process scope.
WorkResult.BusinessError(errorCode, errorMessage)newThrowErrorCommand(code, msg)Domain validation failed. BPMN boundary event catches by errorCode. Does NOT burn retry budget.
WorkResult.Compensated()newCompleteCommand() (no vars)Compensation job completed. Part of saga rollback. No output variables needed.
 
// Static factory methods — prefer these
WorkResult.completed(Map.of("orderId", id));   // with variables
WorkResult.completed();                          // no output needed
WorkResult.businessError("DOC_MISSING", "Required document not uploaded");
WorkResult.compensated();                        // saga rollback step

Exception Hierarchy

All exceptions extend FrameworkException which carries an errorCode (stable BPMN-safe string) and an errorMessage (human readable). The hierarchy drives both Camunda routing and HTTP response codes.

FrameworkException (abstract)
├── BusinessException          → Worker: throwError | REST: 422
└── TechnicalException (abstract)
    ├── RetryableException     → Worker: rethrow (retry) | REST: 503 + Retry-After: 5
    └── NonRetryableException  → Worker: throwError(TECHNICAL_FAILURE) | REST: 500
ExceptionWorker BehaviorREST BehaviorExample Use Case
BusinessExceptionnewThrowErrorCommand(code, msg) → BPMN boundary event catches itHTTP 422 Unprocessable Entity + errorCodeInvalid state transition, document missing, rule violation
RetryableExceptionRethrows — Camunda decrements job retry counter. Eventually → incidentHTTP 503 + Retry-After: 5 headerDB connection timeout, downstream service unavailable
NonRetryableExceptionthrowError(TECHNICAL_FAILURE) — routes to BPMN boundary for permanent failure handlingHTTP 500 Internal Server ErrorSchema mismatch, config error, corrupt data
IllegalStateTransitionExceptionSubtype of BusinessException. Thrown by AuditableEntity.transition()HTTP 422Trying to approve an already-rejected application
 
// Usage examples:
throw new BusinessException("VALIDATION_FAILED", "Mandatory field missing: email");
throw new RetryableException("DB_TIMEOUT", "Database query exceeded 30s");
throw new NonRetryableException("CONFIG_ERROR", "Missing SMTP host configuration");

IdempotencyGuard

Prevents double-processing of replayed Camunda jobs. Uses a worker_execution table with a composite primary key (business_key, element_id). ON CONFLICT DO NOTHING makes concurrent inserts safe without locks.

-- DDL (already in V1__framework_tables.sql)
CREATE TABLE worker_execution (
    business_key   VARCHAR(200) NOT NULL,
    element_id     VARCHAR(200) NOT NULL,
    completed_at   TIMESTAMP    NOT NULL DEFAULT CURRENT_TIMESTAMP,
    result_hash    VARCHAR(200),            -- optional hash of output, for diagnostics
    PRIMARY KEY (business_key, element_id)
);
ℹ️ BaseWorker calls guard.check() and guard.record() automatically. You never call it manually in your worker. The guard is triggered whenever a businessKey variable is present in the job's variables JSON — extracted by convention.

OutboxRelay — Transactional Outbox Pattern

Solves the dual-write problem: you need to save a domain entity AND start/correlate a Camunda process, but the two are on different systems. Write both in one DB transaction; the outbox poller dispatches async.

Two Methods to Write

// In a @Transactional service method:
outboxRelay.publishStart(StartProcessCommand.withVariables(...));    // kind=START
outboxRelay.publishCorrelate(new CorrelateMessageCommand(...));     // kind=MESSAGE

Outbox Table

-- Also in V1__framework_tables.sql
CREATE TABLE process_outbox (
    id             UUID         PRIMARY KEY,
    aggregate_type VARCHAR(100) NOT NULL,
    aggregate_id   VARCHAR(200) NOT NULL,
    kind           VARCHAR(20)  NOT NULL,   -- 'START' | 'MESSAGE'
    payload        TEXT         NOT NULL,   -- JSON-serialized command
    created_at     TIMESTAMP    NOT NULL DEFAULT CURRENT_TIMESTAMP,
    dispatched_at  TIMESTAMP               -- NULL = pending, NOT NULL = done
);
CREATE INDEX idx_process_outbox_undispatched
    ON process_outbox (created_at) WHERE dispatched_at IS NULL;

Poll Mechanism

The @Scheduled(fixedDelayString = "${framework.outbox.poll-interval:PT2S}") poll runs every 2 seconds by default. Uses SELECT ... FOR UPDATE SKIP LOCKED so multiple pods don't steal each other's rows. Requires @EnableScheduling on your @SpringBootApplication class.

⚠️ FOR UPDATE SKIP LOCKED is Postgres-specific. In tests using H2 in MODE=PostgreSQL, this usually works, but if it fails, run outbox tests against a real Postgres (Testcontainers).

AuditableEntity<S>

Abstract base for domain aggregates that need a typed state machine + audit trail. Extend this on your JPA entity.

@Entity
@EntityListeners(AuditColumnListener.class)
public class Application extends AuditableEntity<ApplicationStatus> {

    @Enumerated(EnumType.STRING)
    private ApplicationStatus status;

    private Instant createdAt;   // auto-stamped by AuditColumnListener
    private Instant updatedAt;
    private String  createdBy;   // from X-User-Id header
    private String  updatedBy;

    @Override
    protected Set<ApplicationStatus> allowedTransitions(ApplicationStatus from) {
        return switch (from) {
            case DRAFT      -> Set.of(SUBMITTED);
            case SUBMITTED  -> Set.of(UNDER_REVIEW, REJECTED);
            case UNDER_REVIEW -> Set.of(APPROVED, REJECTED);
            case APPROVED, REJECTED -> Set.of(); // terminal
        };
    }

    // getStatus() / setStatus() / appendAuditNote() — implement these
}

// Usage:
application.transition(ApplicationStatus.APPROVED, "Reviewer: documents verified");
// Throws IllegalStateTransitionException if not in allowedTransitions

VariableMapper

Anti-corruption layer between raw Camunda job variables (JSON) and typed Java records. Uses Jackson 2.x (not Jackson 3.x which Boot 4 defaults to — this matters because Camunda 8.9 uses Jackson 2.x).

// Map a JSON string → typed record
MyVars vars = variableMapper.map(job.getVariables(), MyVars.class);

// Map a Map → typed record
MyVars vars = variableMapper.map(rawMap, MyVars.class);

// Serialize a result record to a Map for Camunda variable output
Map<String, Object> out = variableMapper.toMap(resultRecord);

After binding, VariableMapper validates all record components that are not annotated @Nullable are non-null. If any required field is missing from the job payload, it throws VariableBindingException immediately — not deep in the business logic.

framework-security-starter

Activated when org.springframework.security.oauth2.jwt.Jwt is on classpath (i.e., you added spring-boot-starter-oauth2-resource-server).

Beans registered

JwtAuthenticationConverter: Reads roles from the dot-path in framework.security.jwt.roles-claim (default: realm_access.roles — Keycloak shape). Prepends ROLE_ prefix. All role strings uppercased.

CorsConfigurationSource: Only when framework.security.cors.enabled=true. Maps to /**. Fully configurable via properties.

Wiring your SecurityFilterChain

The framework does not supply a default SecurityFilterChain. That's intentional — your service decides which paths need authentication. Wire the framework beans in your own chain:

@Bean
public SecurityFilterChain securityFilterChain(HttpSecurity http,
        JwtAuthenticationConverter frameworkJwtAuthenticationConverter) throws Exception {
    http
        .oauth2ResourceServer(oauth -> oauth
            .jwt(j -> j.jwtAuthenticationConverter(frameworkJwtAuthenticationConverter)))
        .authorizeHttpRequests(auth -> auth
            .requestMatchers("/actuator/health/**").permitAll()
            .anyRequest().authenticated());
    return http.build();
}

Properties

framework:
  security:
    jwt:
      roles-claim: realm_access.roles   # dot-path into JWT claims
      role-prefix: ROLE_
    cors:
      enabled: false
      allowed-origins: ["https://app.example.com"]
      allowed-methods: [GET, POST, PUT, DELETE, OPTIONS]
      allowed-headers: ["*"]
      allow-credentials: false
      max-age: PT1H

framework-observability-starter

MdcCorrelationFilter

Reads X-Correlation-Id from each HTTP request. If absent and generate-if-absent=true, generates a UUID. Puts it in MDC under key correlationId. Echoes it in the response header. Also reads X-Tenant-Id → MDC. Both are cleaned up in finally.

FrameworkCounters

Domain-level business metrics with consistent naming: <domain>_<state>_total. Not auto-registered (domain name is application-specific). Instantiate once per domain:

@Bean
public FrameworkCounters orderCounters(MeterRegistry registry) {
    return new FrameworkCounters(registry, "orders");
    // Produces: orders_created_total, orders_approved_total, etc.
}

// Usage in domain service:
orderCounters.created();       // orders_created_total++
orderCounters.approved();      // orders_approved_total++
orderCounters.increment("cancelled"); // orders_cancelled_total++

Properties

framework:
  observability:
    mdc:
      enabled: true
      header-name: X-Correlation-Id
      generate-if-absent: true
      tenant-id-header-name: X-Tenant-Id
    metrics:
      business-counter-prefix: ""  # your domain name

framework-data-starter

AuditColumnListener

JPA entity listener. Reflectively stamps createdAt, updatedAt, createdBy, updatedBy on your entity on @PrePersist and @PreUpdate. Fields that don't exist are silently skipped. User identity comes from the X-User-Id request header. Null-safe — never throws, logs at DEBUG on error.

@Entity
@EntityListeners(AuditColumnListener.class)  // add this
public class MyEntity {
    private Instant createdAt;
    private Instant updatedAt;
    private String  createdBy;
    private String  updatedBy;
}

FlywayNamingConventionValidator

A Flyway Callback that fires at BEFORE_MIGRATE and validates all migration files match V<version>__<snake_case>.sql. Enabled by default. Disable with framework.data.flyway.enforce-naming-convention=false.

EnvironmentPostProcessor Defaults

Sets at lowest priority: hibernate.ddl-auto=validate (not create/update!), open-in-view=false. These are safe production defaults.

Write a Worker — Complete Example

// 1. Define the typed variable record
public record NotifyApplicantVars(
    String businessKey,    // required — idempotency key
    String applicantEmail, // required
    String applicationId,  // required
    @Nullable String reason // optional
) {}

// 2. Implement the worker
@Component
public class NotifyApplicantWorker extends BaseWorker<NotifyApplicantVars> {

    private final EmailService emailService;

    public NotifyApplicantWorker(EmailService emailService,
            VariableMapper mapper, IdempotencyGuard guard, MeterRegistry registry) {
        super(mapper, guard, registry);
        this.emailService = emailService;
    }

    @Override
    protected Class<NotifyApplicantVars> varsType() {
        return NotifyApplicantVars.class;
    }

    @Override
    protected WorkResult doWork(NotifyApplicantVars vars, ActivatedJob job) {
        try {
            emailService.send(vars.applicantEmail(), "Application Update", vars.reason());
            return WorkResult.completed(Map.of("notificationSent", true));
        } catch (EmailTemporaryException e) {
            throw new RetryableException("EMAIL_UNAVAILABLE", e.getMessage(), e);
        } catch (EmailConfigException e) {
            throw new NonRetryableException("EMAIL_CONFIG_ERROR", e.getMessage(), e);
        }
    }

    // 3. Annotate the entry-point and delegate to framework execute()
    @JobWorker(type = "notify-applicant", autoComplete = false)
    public void handle(JobClient client, ActivatedJob job) {
        execute(client, job);
    }
}
ℹ️ Always use autoComplete = false on @JobWorker. The framework calls newCompleteCommand() (or error/throw) itself inside execute(). If you set autoComplete = true, Camunda will auto-complete before your result is dispatched — double-completion error.

Saga Pattern — Orchestration-Based

Sagas in this framework are built in BPMN using subprocess + compensation boundary events. The framework never does hand-coded rollback — BPMN diagrams declare compensation.

Saga Steps

// Step worker (forward path)
return WorkResult.completed(Map.of("bookingId", booking.getId()));

// Compensation worker (rollback path, triggered by BPMN compensation event)
@JobWorker(type = "cancel-booking-compensate", autoComplete = false)
public void handleCompensate(JobClient client, ActivatedJob job) {
    execute(client, job);
}

@Override
protected WorkResult doWork(CancelVars vars, ActivatedJob job) {
    bookingService.cancel(vars.bookingId());
    return WorkResult.compensated(); // ← signals saga rollback step
}

// Add to collection Pre-request Script:
pm.sendRequest({
    url: pm.environment.get('keycloak_url') + '/protocol/openid-connect/token',
    method: 'POST',
    header: { 'Content-Type': 'application/x-www-form-urlencoded' },
    body: {
        mode: 'urlencoded',
        urlencoded: [
            { key: 'grant_type', value: 'password' },
            { key: 'client_id', value: pm.environment.get('client_id') },
            { key: 'username', value: pm.environment.get('username') },
            { key: 'password', value: pm.environment.get('password') }
        ]
    }
}, (err, res) => {
    pm.environment.set('access_token', res.json().access_token);
});

Troubleshooting

🔴
NoSuchBeanDefinitionException: ObjectMapper
The framework provides Jackson 2.x ObjectMapper via @ConditionalOnMissingBean. If your service supplies its own, ensure the injected type is com.fasterxml.jackson.databind.ObjectMapper (Jackson 2.x), not Boot 4's tools.jackson.databind.JsonMapper (Jackson 3.x). Camunda 8.9 uses Jackson 2.x internally.
🔴
Health endpoint DOWN — Camunda client error
All four CAMUNDA_* env vars must be loaded into the process environment. Check with env | grep CAMUNDA. CAMUNDA_REGION is required and case-sensitive.
⚠️
Workers not picking up jobs
Verify: (a) @EnableScheduling is on your @SpringBootApplication class — required for the outbox poller. (b) Your @JobWorker classes are Spring beans. (c) The type attribute on <zeebe:taskDefinition type="..."/> in BPMN matches exactly the string in @JobWorker(type = "...").
⚠️
Flyway migration fails
The shipped V1__framework_tables.sql uses TEXT for the payload column (H2 + Postgres compatible). If production Postgres needs jsonb, add a follow-up migration: ALTER TABLE process_outbox ALTER COLUMN payload TYPE jsonb USING payload::jsonb;
⚠️
FOR UPDATE SKIP LOCKED fails in H2 tests
H2 in MODE=PostgreSQL accepts most Postgres syntax, but FOR UPDATE SKIP LOCKED may fail. Run outbox-specific tests with Testcontainers pointing at real Postgres.
ℹ️
User task not found after process start
Camunda's user task search index is eventually consistent. CamundaProcessService.findActiveUserTaskKey() retries 5 times with exponential backoff (200ms, 400ms, 800ms, 1600ms). If it still fails, the process may be at a different state. Check Operate.
ℹ️
MDC not showing in logs
Ensure your log pattern includes MDC keys. Example Logback pattern: %d{ISO8601} [%X{correlationId}] [%X{processInstanceKey}] %-5level %logger{36} - %msg%n
